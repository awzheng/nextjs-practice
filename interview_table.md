# Technical Interview Map

**VCam** = virtual 360° camera emulator on Firecracker-microVM (Go/Docker) · **RAUC** = Yocto x86-64 OTA streaming via AWS IoT · **Soak** = HIL release pipeline on Terraform/Ansible OTA runners · **DevSearch** = Kotlin/Spring Boot dual lookup, Avro over Kafka to Kubernetes-hosted index · **Allocate** = Rust macOS CPU core governor (XNU QoS, Mach IPC) · **Albedo** = Rust macOS thermal agent (AppleSMC, IOKit, Prometheus) · **CrawlStars** = Go producer-consumer crawler + MongoDB

| Topic | Projects | Keywords | Connection |
| :--- | :--- | :--- | :--- |
| **1.1 Concurrency** (goroutines, channels, WaitGroup, context) | CrawlStars, VCam | 10 goroutine workers, buffered work queue + results channel, sync.Map O(1) dedup, 2000+ pages/min in <15MB | I used 10 worker goroutines and a buffered results channel in CrawlStars to reach 2000+ pages/min by decoupling HTML fetch rate from MongoDB upsert rate, so slow writes never blocked crawling.<br><br>I used per-request goroutines with context deadlines in VCam to serve RTSP and camera-API clients concurrently by bounding each session, so one stalled Camera Manager poll couldn't leak goroutines inside the microVM. |
| **1.2 Memory & Pointers** | CrawlStars, Allocate | pass-by-value vs pointer, escape analysis, GC pressure, Rust FFI daemon, raw libxpc, manual xpc_retain/release | I used pointers to page structs in CrawlStars to hold RSS under 15MB by sending references over the results channel instead of copying every page body at each worker handoff.<br><br>I used raw pointers with manual xpc_retain/release in Allocate's Rust FFI daemon to avoid leaking XPC connections by tracking lifetimes by hand, since libxpc returns pointers into dictionary storage that die with the handler. |

| **1.4 Standard Library** (os, os/exec, io, net) | RAUC, CrawlStars, Allocate | net/http, io.Reader, HTTP range requests, adaptive block hash index, taskpolicy exec, SIGTERM | I used streaming range reads in RAUC — Node streams, same contract as Go's io.Reader — to cut OTA bandwidth 98% by installing only changed blocks instead of buffering a 1.4GB bundle.<br><br>I used net/http with a 15s timeout in CrawlStars to stop 10 workers stalling on dead hosts by bounding every fetch at the transport layer rather than in application logic.<br><br>I used process spawning of /usr/sbin/taskpolicy in Allocate (Rust's Command, Go's os/exec equivalent) to reroute processes to E-cores by driving Apple's supported tool instead of private kernel APIs. |
| **2.1 Kernel vs. User Space** | Allocate, Albedo, VCam | XNU Kernel, Mach, Apple IOKit, ring 0/3, KVM, Firecracker guest kernel | I used user-space XNU QoS requests in Allocate to cut background CPU 79% by asking the kernel scheduler to demote processes, since no user-space process can preempt another itself.<br><br>I used IOKit and AppleSMC in Albedo to surface 18 sensors from user space by crossing into kernel drivers through supported interfaces, since raw SMC registers are unreachable from a normal process.<br><br>I used Firecracker's separate guest kernel in VCam to isolate app code from the CTM host by giving the workload its own kernel boundary instead of sharing the device's. |
| **2.2 System Calls** | Allocate, Albedo | Darwin proc pidinfo, Mach CPU ticks per 500ms, AppleSMC, IOReport, mode switch | I used proc_pidinfo and Mach CPU-tick calls in Allocate to sample per-process CPU every 500ms by batching one snapshot per tick, since each syscall costs a user→kernel mode switch.<br><br>I used IOReport counters in Albedo to derive DVFS residency and PPW by reading state the kernel already maintains, so the monitor's own syscall cost stayed near zero. |
| **2.3 Processes & Threads** | Allocate, CrawlStars | POSIX thread policies, XNU QoS, launchd daemon, PID lifecycle, goroutine vs OS thread | I used a separate launchd daemon in Allocate to keep 100% app uptime by isolating the SwiftUI app's address space from the governor's, so a UI crash can't drop in-flight core overrides.<br><br>I used goroutines rather than separate processes in CrawlStars to share one sync.Map visited set across 10 workers by keeping them in a single address space, which processes would need IPC to do. |
| **2.4 Linux Isolation** (namespaces, cgroups) | VCam | Docker net/PID/mount namespaces, bind :80 in-guest, CTM DNAT :20080/:20554, manifest CPU/memory, OOM kill | I used network-namespace isolation in VCam to bind the real camera's :80 and :554 inside the guest by letting the CTM firewall DNAT them to :20080/:20554, avoiding host port collisions.<br><br>I used manifest-declared CPU and memory limits in VCam to keep the emulator from starving the CV pipeline by capping what it consumes, since namespaces control what it sees but not what it uses. |

| **3.2 MicroVMs** (fast cold-start, low overhead) | VCam | Firecracker, ~125ms boot, ~5MiB overhead, minimal virtio device model, no BIOS, jailer | I used Firecracker's minimal virtio device model in VCam to run a camera stand-in on constrained ARM64 CTM hardware by trading legacy device emulation for ~125ms boots and megabytes of memory overhead. |
| **3.3 Security Posture** (least privilege, drop root, egress filtering) | VCam, RAUC, DevSearch | MioApp manifest MQTT entitlements, declared ports, non-root, inbound-only DNAT, presigned S3 URL, guarded fallback | I used declared MQTT entitlements and explicit ports in VCam's MioApp manifest to apply least privilege by granting the emulator only the topics it needed, so a compromised app couldn't publish fleet-wide commands.<br><br>I used Lambda-validated presigned S3 URLs in RAUC to avoid open device egress by scoping each fetch to one expiring object instead of letting the updater reach arbitrary endpoints.<br><br>I used a guarded DataLink fallback in DevSearch to contain blast radius by gating the legacy lookup behind explicit conditions rather than querying both stores on every request. |

| **4.2 The Control Loop** (controller pattern) | RAUC, Soak, Allocate, Albedo | AWS IoT device shadow, desired vs reported, shadow delta, level-triggered, setpoint + hysteresis band | I used AWS IoT device shadows in RAUC to converge firmware versions by setting desired state and letting each device diff it against reported state, then act and re-report.<br><br>I used that same desired/reported loop in Soak to drive 48h installs by having the framework set a desired bundle and the Radio reconcile Tuba CV through stage-and-reboot.<br><br>I used throttle and release thresholds in Allocate to hold 100% app uptime by re-evaluating actual CPU against desired state every 500ms and acting only on the delta.<br><br>I used a temperature setpoint with a hysteresis gap in Albedo to achieve 12°C cooling by requesting E-core holds from Allocate until sensor state converged, with the gap preventing oscillation. |

## Gaps — state these plainly, don't bluff

- Consumed Firecracker through `mioappd`; haven't written VMM or jailer config directly.
- Deployed to Kubernetes but haven't authored a CRD + controller with controller-runtime.
- Kernel depth is XNU/Mach, not hands-on Linux namespaces/cgroups — concepts transfer, syscall names don't.
- Governors are setpoint + hysteresis, not PID control. Never say "PID controller"; on the resume "PID-level" means per-process-ID.
